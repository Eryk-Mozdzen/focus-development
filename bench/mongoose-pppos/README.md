# PPPoS adapter for Mongoose 7.23

This folder adds RFC 1662 serial framing to Mongoose's built-in PPP L2. It
does not duplicate PPP negotiation, IPv4/IPv6 handling, or the TCP/IP stack:
those remain in `bench/mongoose`. `mg_pppos_input()` unescapes and validates
the PPP FCS, then makes complete frames available to Mongoose's normal PPP
receive path. The Mongoose driver transmit callback escapes the complete
HDLC frame (including its FCS) and writes it to the serial transport.

Compile `mg_pppos.c` alongside the application's Mongoose sources. Configure
Mongoose to use its built-in stack (`MG_ENABLE_TCPIP=1`) and disable any other
TCP/IP stack, including lwIP (`MG_ENABLE_LWIP=0`). Include `mongoose.h` and
`mg_pppos.h`.

```c
static struct mg_pppos pppos;
static struct mg_tcpip_if netif;

// UART callbacks are application-specific. write_serial() must enqueue or
// transmit the entire encoded frame and return its byte count. uart_init() may
// be NULL.
mg_pppos_init_state(&pppos, write_serial, uart_init, uart_link_is_up, uart);
netif.driver = mg_pppos_driver(&pppos);
netif.driver_data = &pppos;
netif.l2type = MG_TCPIP_L2_PPP;
netif.enable_dhcp_client = false;  // Mongoose PPP expects negotiated/static IP
mg_tcpip_init(&mgr, &netif);

// From the UART RX callback/task, pass every received byte chunk:
mg_pppos_input(&pppos, bytes, count);
```

Call `mg_pppos_input()` in a serialized context with Mongoose polling, or
protect shared state with application synchronization. RX slots are bounded;
`rx_dropped`, `rx_bad_fcs`, and `rx_overflow` expose receive loss/corruption
counts. The adapter currently assumes asynchronous HDLC framing with
address/control bytes present as generated by Mongoose PPP, and uses the
default RFC 1662 control-character escaping map. Mongoose's PPP implementation
is client-side and retains its existing negotiation limitations.

## Linux PTY example

[`example/linux_example.c`](example/linux_example.c) opens a serial device in
raw mode at 115200 baud, feeds received bytes into the adapter, and serves a
small HTTP response on port 8080 once the PPP interface is up. Set the local
and peer IP addresses in the example to match the PPP peer. The CMake project
accepts a separate Mongoose checkout path, so this directory can be used as
its own repository.

Build the example from the repository root, pointing `MG_MONGOOSE_DIR` at a
Mongoose checkout:

```sh
cmake -S mongoose-pppos/example -B mongoose-pppos/build \
  -DMG_MONGOOSE_DIR=/path/to/mongoose
cmake --build mongoose-pppos/build
```

To run the `pppd` integration over two PTYs, install `socat`, `pppd`, and
`curl`, then run the PTY target as root. `pppd` requires root to run this test
peer with `noauth`:

```sh
sudo cmake --build mongoose-pppos/build --target run-pty
```

The runner starts a PTY pair, runs `pppd` on one side and the Mongoose example
on the other, then checks that HTTP reaches Mongoose through the PPP link.
For manual PTY setup, run `example/create_pty.sh`, then pass its Mongoose-side
path to `pppos-linux` and configure `pppd` to use the other path.
